EdgeSidekick User Guide

A local multi-agent AI workbench. This guide covers install/start, workbench vs social mode, chat, themes, Skills, and basic settings.

Install & start Workbench vs Social Chat Themes Skills Settings

1. Install & start

From source

python -m pip install -r requirements.txt
python main.py

Open http://127.0.0.1:8787 in your browser.

Desktop

  • Windows: run start-desktop.bat, or use the installer / portable zip.
  • Kylin / Linux: .deb / AppImage, or build the desktop app per README.
On first launch, pick a workspace folder. History and Memory stay on your disk by default.

2. Workbench vs Social

Workbench

Built for engineering tasks: main/sub-agents, file edits, shell, browser sandbox, task panel. Best for coding, docs, and commands.

Social / Session

Conversation-first UI with session lists and DM-style chat, still backed by the same agents. Best for ongoing Q&A and topic threads.

Both share the same local runtime and model config.

3. Multi-agent chat

  • Send a message; replies stream over SSE.
  • The main agent can orchestrate sub-agents. Writes, shell, and Memory changes usually need human approval.
  • Attachments, stop, edit & resend, and optional file restore are supported.

4. Themes & language

  • Light clean for daytime focus.
  • Dark immersive for long night sessions.
  • Chinese / English UI; preferences can persist separately for the site and the app.

5. Skills

  • Drop packs under src/skills/ (or the tenant skills directory).
  • Invoke with /skill so tools load on demand.
  • Bundled examples cover writing, debugging, decks, and more.

6. Basic settings

  • Models: separate main / sub / compress models; bring your API key or use Ollama.
  • Workspace: Settings → pick a local folder; switch among recent workspaces.
  • Browser sandbox: desktop BrowserView / Web Playwright; Select Mode + browser_* tools.
  • Memory / Tasks / MCP: append or rewrite MEMORY.md (with approval); track tasks; hook external tools via MCP.
API keys and tokens stay on this machine. Clear personal tokens under src/data before shipping a demo tree.

See root README.md for deeper technical notes.
